# Patch 生成方法 — Feature 合并回上级

## 核心原则

**生成 patch,不是覆盖**。feature HLD 的内容作为变更建议,呈现给用户审阅,确认后才写入目标 HLD。

## Diff 分析方法(逐章对比)

### §1 概述

对比 feature 概述 vs 目标 HLD 概述:
- 若 feature 引入新概念 → 标记"概述新增一句"
- 若无变化 → 标记"无变更"

### §2 处理流程图

对比两个 mermaid 图:
- 识别 feature 流程图里新增的 step(目标 HLD 没有的)
- 识别被修改的 step(描述变化)
- 识别被删除的 step(feature 移除了某个分支)

**判定方法**:按 mermaid 节点 ID 对比,不是按文本对比。

### §3 数据模型

对比表/字段:
- **新增表**:feature HLD 有,目标 HLD 没有
- **修改表**:两边都有同名表,但字段有差异
  - 新增字段:feature 有,目标没有
  - 修改字段:类型/约束变化
  - 删除字段:feature 没有,目标有(罕见,需重点确认)
- **删除表**:feature HLD 没有,目标 HLD 有(罕见,需重点确认)

### §4 接口设计

对比接口:
- **新增接口**:feature HLD 有,目标 HLD 没有
- **修改接口**:同名接口的签名/字段有差异
  - 新增字段
  - 修改字段类型
  - 删除字段(需重点确认)
- **删除接口**:feature HLD 没有,目标 HLD 有(罕见,需重点确认)

## Patch 输出格式

```markdown
## Patch — [feature HLD 文件名] → [目标 HLD 文件名]

### §1 概述
- [无变更]
- 或:新增一句 "[内容]"

### §2 处理流程图
- 新增 step N+1: [描述]
- 修改 step M: [旧] → [新]
- [无删除]

### §3 数据模型
- 新增表: [表名] (字段: [字段列表])
- 修改表: [表名]
  - 新增字段: [字段名] [类型] [约束]
  - 修改字段: [字段名] [旧类型] → [新类型]
- [无删除]

### §4 接口设计
- 新增接口: [方法名] [签名]
- 修改接口: [方法名]
  - 新增字段: [字段名] [类型]
  - 修改字段: [字段名] [旧类型] → [新类型]
- [无删除]
```

## 写入规则

用户确认 patch 后:

1. 用 edit 工具按 patch 逐条写入目标 HLD
2. 目标 HLD 版本号 +0.1(如 v1.0 → v1.1)
3. 修订记录表加一行:
   ```
   | v1.1 | YYYY-MM-DD | <姓名> | 合并 [feature HLD 文件名] | <审核人> |
   ```
4. 文件名同步更新版本号
5. 重跑 `check_hld_structure.py` 确认合规
