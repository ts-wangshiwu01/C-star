# 模板规范 — 8 字段头部 + 4 章结构

## 1. 8 字段头部(必填,顺序固定)

每份 HLD 第一段必须是这 8 个字段:

```markdown
**项目名称**：<项目全称>
**文档类型**：High Level Design — [项目级 | 服务级 | Feature 级]
**创建日期**：YYYY-MM-DD
**创建人**：<姓名>
**审核人**：<姓名>
**版本号**：vX.Y.Z
**状态**：<草稿 | 审核中 | 已发布 | 已归档>
```

**注意**:
- 创建人/审核人不能是占位符(`[姓名]` / `张三`),用真实姓名
- 8 字段后立即跟修订记录表,不留空行

## 2. 修订记录表(紧跟头部)

```markdown
| 版本号 | 修订日期 | 修订人 | 修订内容 | 审核人 |
|--------|----------|--------|----------|--------|
| v1.0 | YYYY-MM-DD | <姓名> | 初稿创建 | <姓名> |
```

## 3. 4 章结构(固定,不可增减)

```
## 1. 概述
## 2. 处理流程图
## 3. 数据模型
## 4. 接口设计
```

不擅自加章节。架构/依赖关系在 `architecture/` 独立定义,决策点/非功能不写。

## 4. 各章详细度(按级别递增)

| 章节 | 项目级 | 服务级 | Feature 级 |
|---|---|---|---|
| 概述 | 整体定位 + ADR 约束 | 服务角色 + 边界 | ticket + 一句话 |
| 流程图 | 系统级(服务间) | 服务内(handler/repository) | feature 全链路(每一步) |
| 数据模型 | 实体关系表 | 表 + 字段 + 索引 | 变更清单(新增/修改) |
| 接口设计 | 接口分类 + 归属 | gRPC 方法 + proto 签名 | 具体字段级变更 |

## 5. 处理流程图规范

- 必须用 mermaid 语法(`sequenceDiagram` 或 `flowchart`)
- 必须体现"谁流转给谁"
- 项目级:服务间流转
- 服务级:服务内 handler → service → repository 流转
- Feature 级:从入口到落库的每一步

## 6. 版本号升级规则

| 修改性质 | 版本号变化 | 修订记录 |
|---|---|---|
| 需求/规格变更 | +0.1(v1.0 → v1.1) | 是 |
| 新增章节内容 | +0.1 | 是 |
| 文字修订(不影响需求/规格) | 不变 | 否 |

版本号变化必须同步更新文件名。
